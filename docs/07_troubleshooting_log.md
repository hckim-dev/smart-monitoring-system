# 문제 해결과 설계 판단

[문서 안내](README.md) · [동작 확인](08_setup_and_operation_guide.md#시나리오별-검증)

개발 중 기록된 문제를 현재 구현과 연결했습니다. 당시 관찰은 기존 개발 기록이며, 아래 계산값과 구분합니다.

## 1. 서보 동작: 각도보다 타이머 입력부터 확인

**문제:** 90°를 요청했는데 약 45°만 움직였다는 관찰이 있었습니다.

**접근:** 각도 인자보다 타이머 입력 클럭 → prescaler → 펄스 폭 순서로 확인합니다. 현재 APB1 분주 설정에서 TIM2 입력은 96MHz이며, 이를 기준으로 1µs tick과 20ms 주기를 설정합니다.

| 설정 | 현재 값 | 의미 |
| --- | --- | --- |
| TIM2 PSC | 95 | 96MHz / 96 → 1µs tick |
| TIM2 ARR | 19999 | 20ms → 50Hz |
| CCR1 | 500 / 1500 | 개방·차단 목표의 high 폭 |

입력을 48MHz로 잘못 가정해 PSC를 47로 정하면 실제 주기는 10ms, CCR1=1500의 high 폭은 750µs가 됩니다. 이 계산만으로 서보의 실제 각도까지 확정할 수는 없습니다.

**현재 구현:** [option.h](../stm32-firmware/option.h)의 타이머 클럭 계산과 [timer.c](../stm32-firmware/timer.c)의 분주 설정을 사용합니다. 물리 각도와 파형은 실제 부하 조건에서 확인할 항목입니다.

## 2. 전원과 계측: ADC 변화의 원인 분리

**문제:** 팬·LED를 켠 뒤 ADC값이 약 1270에서 1530으로 변했다는 기록이 있습니다.

**접근:** `ADC ≈ VIN / VREF × 4095` 관계를 기준으로 입력 전압, 기준 전압, 접지 전위를 함께 확인합니다. 가변저항과 기준 전압이 같은 전원에서 움직이면 비율이 유지될 수도 있으므로, ADC 상승만으로 VREF 강하를 확정하지 않습니다.

기존 기록은 서보 측 470µF·모터 드라이버 측 100µF 캐패시터와 접지 배선을 대책으로 제시했습니다. 전후 파형이 남아 있지 않아 개선 효과는 수치로 제시하지 않습니다.

**설계 판단:** 전원 문제와 소프트웨어의 반복 명령 처리는 나눠 다룹니다. 현재 차단 래치는 명령 반복을 줄이며, 입력 전압의 변동 자체를 보정하지는 않습니다. 관련 배선은 [하드웨어 문서](03_hardware_and_pinmap.md#전원과-노이즈)에 정리했습니다.

## 3. 반복 명령: 송신과 구동에 각각 가드 배치

**문제:** 위험 샘플이나 같은 버튼 입력이 반복되면 동일한 제어 요청이 누적될 수 있습니다.

| 위치 | 처리 | 효과 |
| --- | --- | --- |
| Qt `m_isValveClosed` | 자동 차단 송신 성공 반환 후 래치 설정 | 자동 명령 반복 감소 |
| MCU `Valve_Set_State()` | 같은 상태 요청이면 출력 함수 호출 생략 | 중복 GPIO·CCR 갱신 감소 |

**설계 판단:** 중복 요청 억제와 상태 동기화는 별개입니다. 물리 버튼이나 MCU reset으로 상태가 바뀌면 Qt 래치와 다를 수 있습니다. 다음 확장 시에는 MCU 상태 회신과 명령 ACK가 우선 과제입니다.

서보 PWM은 목표 설정 후에도 계속 출력합니다. 중복 갱신을 생략하는 처리가 PWM 정지나 소음 제거를 뜻하지는 않습니다.

→ [상태 소유권과 복구 동작](01_system_architecture.md#상태-소유권)

## 4. TCP 스트림: 송신 직렬화와 수신 재조립

**문제:** 한 번의 read가 한 프레임과 일치하지 않고, 명령과 JPEG가 한 연결을 공유합니다.

**구현:** Android는 명령·영상 송신에 같은 Mutex를 사용합니다. Qt는 길이 헤더와 누적 버퍼로 분할된 JPEG를 조립하고, 남은 메시지를 반복 처리합니다. 허용 영상 크기 10MiB 안에서는 길이 헤더의 최상위 바이트가 0이므로 텍스트와 구분할 수 있습니다.

**설계 판단:** 송신 중 바이트가 섞이지 않도록 하는 것과 수신 경계를 복원하는 것이 함께 필요합니다. 후속 확장에서는 명시적인 message type, 수신 버퍼 상한, 오류 후 재동기화가 필요합니다.

→ [메시지 형식과 파서](02_protocol_specification.md)

- **영상 부하:** 느린 네트워크에서 송신 대기 프레임 제한과 제어 명령 지연 측정.
